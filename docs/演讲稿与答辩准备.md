# 课堂展示讲稿

建议总时长 10—12 分钟；正文 11 页。

## 第 1 页　汽油辛烷值损失优化

大家好，我的项目是基于粒子群算法的汽油辛烷值损失优化。项目围绕汽油生产操作参数的离线优化展开，工作重点是计算实现与验证。主要回答两个问题：同一个 PSO 怎样通过批量计算减少耗时，以及在代理模型上得到的优化结果能解释到什么程度。整个项目由我作为单人成组提交，AI 参与编写和验证的部分在 README 中有完整声明。

## 第 2 页　计算问题与课程技术

对于每一个样本，原料辛烷值等四项性质保持不变，23 个操作变量组成一个粒子的位置。评价一个位置需要预测产品 RON 和硫含量。RON 损失等于原料 RON 减去预测的产品 RON，硫含量必须在零到五之间。PSO 是要实现的优化算法，NumPy 和并行计算是本项目用到的课程技术。因此工作重点不是简单调用一个优化包，而是解释瓶颈、实现计算过程，并用相同预算做比较。

## 第 3 页　数据整理与变量设置

原始工作表存在多行表头，所以我按稳定的仪表位号提取数据，避免直接按列偏移取错变量。23个操作量和4项原料性质的顺序在数据字典中明确固定。EH103存在两个同名温度测点，本项目选择TXE_3201A并记录具体位号和范围。模型训练只使用较早的数据，较新的65条作为留出集，标准化和搜索边界都只从训练段计算。核心网络和PSO均由NumPy实现，保存权重与运行脚本，便于检查和复跑。

## 第 4 页　代理模型先接受独立检验

两个模型只在训练段拟合标准化参数，通过训练段内部验证选择种子和训练轮数，再在完整训练段重新训练。最终较新的65条测试数据不参与模型选择。结果中 RON 的 MLP 明显好于训练均值，但岭回归更好；硫含量的 R 方是负数，说明它不能可靠适应留出工况。这里我没有只展示好的拟合图，也没有因为结果不利就更换测试划分。这个限制会直接影响对后面优化结果的解释。

## 第 5 页　同一算法的两种计算实现

这两个版本只改变计算的组织方式，没有改变搜索语义。每轮先生成同形状的两组随机数，再更新整个种群，所有评价完成后才更新全局最优，避免循环版无意中变成异步算法。归一化消除各操作变量的量纲差异。越界位置会被裁剪，相应速度置零。对不可行点使用大常数加违反量，避免所有不可行点得到同一个分数而无法寻找可行区域。主要瓶颈是循环版重复进行小矩阵计算和 Python 调用。

## 第 6 页　正确性与随机算法验证

测试不只检查代码能否运行。例如 Sphere 的最小值已知是零，可以验证搜索方向与最优值更新；线性目标的最优点在边界，可以验证裁剪；合成模型可以独立检查不可行约束。网络前向还有一个单独的标量计算参照。实际汽油目标的循环版与向量化版轨迹误差在浮点精度范围内。解析函数的20次重复运行也显示了局限：10维多峰函数没有都到达零，因此不能宣称当前算法和预算能够保证全局最优。

## 第 7 页　向量化明显减少当前实现的耗时

这页是核心性能结果。粒子数分别为32、128、300，其他条件完全一致。循环版耗时中位数约31、123、279毫秒，批量版约1.6、2.5、4.3毫秒，相当于约19、49和65倍的耗时比。规模越大，小函数调用开销被摊薄得越充分。这不表示 PSO 比其他优化算法快，也不是对 C++ 库的比较；它仅证明当前清晰的 Python 循环基准可以通过数组批量计算有效优化。五次原始记录均保留供检查。

## 第 8 页　相同评价预算下的解质量

为了区分实现加速和优化方法本身的效果，我还在同一批固定模型上比较了 PSO 和随机搜索。两者严格使用相同的候选评价次数，而不是相同迭代数。PSO 的预测损失通常更低，但随机搜索的一次大批量预测很高效，实际耗时更短。所以这里存在质量和时间的不同维度，不能用更低损失推出运行更快。箱线图混合了五个样本的结果，原始表中保留每个样本每个种子的记录，不能把它当作100个独立工业工况。

## 第 9 页　近零预测损失暴露了模型风险

对325条样本逐条演示时，模型几乎都允许搜索到预测RON接近原料RON的点，损失接近零。这个结果看起来很好，但不能当作工业改善。首先硫含量预测泛化不足，其次优化后候选与训练数据的距离明显变大。即使每列都限制在训练最小最大值内，自由组合的工况也可能偏离训练联合分布。这里距离仅是诊断，不是误差的上界。我的结论是优化器在寻找代理模型的边界，后续需要更多数据或加入局部信赖域与不确定性约束。

## 第 10 页　短任务并行未获得加速

并行测试没有得到预想中的收益。对12个短任务，串行中位时间约0.127秒，两个和四个进程分别约0.586和0.605秒。Windows进程启动和模块导入需要成本，任务计算太短，这部分开销无法被摊薄。每种进程数的样本结果都相同，所以这是性能适用范围的问题，而不是计算错了。我保留首次两进程运行较慢的记录，没有删除不利数据。若扩大任务规模或复用进程池，可能改善，但本项目不把未经测试的推测当成结果。

## 第 11 页　结论与复现入口

本项目完成了明确的计算问题、自己的核心实现、正确性检验和公平实验。最主要的正面结果是向量化的计算收益；负面结果包括短任务并行开销以及硫含量模型泛化不足，二者都帮助界定方法适用范围。复现可以先运行测试，再运行单样本演示；完整实验脚本会从头训练并输出记录。报告和所有数字由记录汇总生成。方法参考资料列在报告末尾，数据来自给定附件；AI辅助的范围已披露。谢谢。

# 常见答辩问题

**为什么使用 PSO？** 作为汽油操作参数问题的无梯度约束优化基线，重点是实现与计算比较。它不保证全局最优。当前 ReLU 代理大部分区域有梯度，也可以考虑梯度法；本项目未声称 PSO 是最优选择。

**自己的工作是什么？** 变量位号映射、范围差异核对、两个 NumPy 网络、同步 PSO 两种计算方式、约束处理、正确性和性能实验以及复现工程。AI 参与代码和文档编写，不能把 AI 辅助隐藏成纯手工实现。

**为什么不把近零预测损失直接视作工业收益？** 时间留出检验表明模型存在预测误差，优化工况还可能偏离训练联合分布。因此这里只能验证代理模型上的计算行为，真实收益需要额外验证。

**为什么岭回归更好却使用 MLP 优化？** 本项目预先固定双MLP作为优化所用的代理，先独立报告预测基准，不依据留出结果更换优化器中的代理。本项目不主张该 MLP 最佳。

**模型差是否意味着项目失败？** 它限制工业用途，但不抹去同模型同输入下的实现等价与性能比较。课程允许没有预期改进，要求证据和原因分析。

**搜索轮次是否等于装置操作步骤？** 不等于。搜索轮次属于数值算法；装置操作还涉及单次调整幅度、设备联动和动态响应，本项目没有将两者混用。

**怎么解释加速倍数？** 基准是单线程 Python 逐粒子、小矩阵反复调用。向量化减少开销，没有改变渐近计算量，也未比较 C++ 库或承诺跨机器相同比值。
