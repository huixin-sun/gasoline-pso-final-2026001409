## 项目与主要结论

固定一个工况的 4 项原料性质，利用两个 NumPy MLP 分别预测产品 RON 和硫含量，用自行实现的同步全局最优 PSO 优化 23 个操作变量。研究重点为相同算法的不同计算实现及适用范围。

- 同样的输入、模型、随机数与评价预算下，逐粒子和向量化 PSO 的目标轨迹最大绝对差约 `1.42e-14`。
- 32 / 128 / 300 粒子、20 轮、5 次预热后测量的中位耗时比约为 18.9 / 49.4 / 65.1。基准是本项目的 Python 逐粒子实现，不是 C++ 库，也不是不同算法之间的速度比较。
- 5 个固定留出样本各 20 个种子，在 7,776 次评价预算下，PSO 得到更低的代理损失；均匀随机搜索实际耗时更短。原始逐样本、逐种子记录保留。
- 12 个短任务使用多进程更慢，进程启动和通信成本超过计算收益。
- 时间留出集上硫含量 MLP 的 R² 为负，优化点的训练支持程度较弱。因此代理模型给出的近零损失和硫合格不能解释为已验证的工业收益。

所有报告数字均来自本项目实际运行记录。模型不足、并行未加速及高维解析函数残差均如实保留。

## 安装与最小可运行示例

建议 Python 3.12（核心源码使用 Python 3.11+），CPU 即可，无 GPU 要求。从项目根目录执行：

```bash
python -m venv .venv
# Windows PowerShell: .\.venv\Scripts\Activate.ps1
# macOS / Linux: source .venv/bin/activate
python -m pip install -r requirements.txt
python -m unittest discover -s tests -v
python scripts/demo.py
```

核心模型、PSO、实验及测试只依赖 NumPy。demo 使用随包提供的 NPZ 权重和已记录的边界，优化样本 133，32 粒子、30 轮，不改变正式结果文件。预计几秒内完成；不同硬件耗时不同。

## 数据、划分与变量映射

数据由用户提供的附件一与附件四提取，来源文件哈希在 `data/provenance.json`。只保留复现所需的变量，不重新打包全部原始工作簿。

`samples.csv` 共 325 行。第 1 列为样本编号，第 2 列为时间，随后是 4 项固定原料性质、23 个仪表位号对应的控制量，以及产品 RON 和硫含量。输入不含产品性质、产品 RON 损失、未来观测标签。按时间排序，较早 260 条训练，较新 65 条留出；训练段内较后 52 条用于选择模型种子与训练轮数。变量集合预先固定，方法配置参考来源见文末；本项目未重新进行全体变量筛选，也不声称这些特征是首次发现。

主搜索框是“物理范围”与“训练段逐列范围”的交集。边界归一化与模型标准化是不同步骤。22 个留出原工况需投影到主搜索框；改善率使用投影工况的模型预测作分母，保留原始实测值和未投影预测以便区分。

## 实验条件与结果解释

正式数值实验：Windows 11，Python 3.12.14、NumPy 2.3.5、OpenBLAS 0.3.30、单 BLAS 线程、CPU 计算，系统报告 20 个逻辑处理器。完整 CPU 标识与 NumPy 配置在 `results/environment.json`。绘图单独使用 Python 3.11.9 / Matplotlib 3.11.2，文档生成使用 ReportLab 4.4.9；绘图和报告不参与性能计时。

同算法实现比较先预热，再重复 5 次；每次包含整个优化器调用，交替计时顺序。进程比较为端到端计时，明确包含启动、载入和通信。算法解质量比较固定候选评价次数，报告种子波动。训练测试集、标准化参数与候选边界均可核对。毫秒级计时易受机器状态影响；跨平台只要求结果在合理数值容差内一致，不要求计时相同。

无全局最优性证明。主框仍可能允许训练联合分布之外的组合。硫含量的预测泛化不佳，模型约束可行与实际装置可行有实质区别。完整应用是每条样本一个种子的演示，随机稳定性结论来自另行记录的多次运行实验。
